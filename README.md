# hct-themed

Marketing site for Hațegan Consulting & Trading (hct.vitrina.promo), a recycling-industry
products and services catalogue. Built as a Bun monorepo with three workspaces:

| Workspace | Role | Stack | Port |
| --------- | ---- | ----- | ---- |
| `admin`   | CMS + admin UI | Payload CMS 3.87, Next.js 16, SQLite | 3000 |
| `web`     | Public site (the deliverable) | Astro 7, Node standalone adapter | 4321 |
| `e2e`     | End-to-end tests | Playwright | - |

- `ro` (default) and `en` locales; `ro` is served without a language prefix.
- All commands run with `bun` (monorepo rules forbid `npm`/`pnpm`/`node`/`vite`).

## Workspaces

### admin (Payload CMS)

Payload config lives in `admin/src/payload.config.ts`. Content is stored in SQLite at
`db/hct.db` (dev auto-login `admin@test.com` / `test1234`). The admin UI is served on
port 3000 and also exposes the Payload REST API that the web site consumes at runtime.

Generated Payload TypeScript types are emitted to `admin/src/payload-types.ts`. After
editing a collection, run `bun run generate:types` and `bun run generate:importmap` in
`admin`.

### Collections

The collections are grouped in the admin UI. Core catalogue collections carry a required,
unique `code` used for URLs, bilingual `name` / `name_en` fields, and `published` /
`promoted` flags.

#### Catalog

| Collection | Notes |
|---|---|
| `products` | Core catalogue entry. `code`, `name`/`name_en`, `description`, `variants` array (code + feature + name + page/url), relationships to `partner`, `category`, `materials` (has many), `main_image` + `images` (product-images). |
| `categories` | `code`, `name`, `description`, `partners` (has many), `illustration` (media), `products`. |
| `partners` | Manufacturer partners. `code`, `name`, `published`, `promoted`, `url`, `logo` (media). |
| `materials` | Material types with `code`, `name`, `name_en`, `description`, `illustration` (media). |
| `projects` | Showcase projects: `code`, `name`, `description`, `published`/`promoted`, `illustration` (media), `page`. |

#### Content

| Collection | Purpose |
|---|---|
| `pages` | CMS-editable pages. `slug` (unique), `title`, `content` (markdown), `published`. |
| `customers` | Customer references. `name`, `url`, `location`, map coordinates (`map_lat`/`map_lng`), `logo` (media). |
| `product-images` | Product gallery images. `caption`, `product` (relationship to products). |
| `media` | Uploaded assets with `caption` and `kind`. |

#### Admin

| Collection | Purpose |
|---|---|
| `users` | Admin authentication accounts. |

#### Plugin

`importExportPlugin` is enabled for all catalogue/content collections, letting you import
and export collection data as JSON from the admin UI.

### Relationships overview

```text
partners ──┐
categories ─┼──> products ──> product-images ──> media
materials ──┘       │
                    └──> categories (via category)
media <── illustration/logo (partners, categories, materials, projects, customers)
```

## web (Astro)

The public site. It is configuration-driven: `src/config/config.toml` is compiled to
`config.generated.json` (regenerated by the toml-watcher on dev/build), and many modules
import the generated JSON. Bilingual content is stored under `src/content/<collection>`
in `english/` and `romanian/` folders, with visible strings driven by `t()` keys in
`src/i18n/{en,ro}.json` and navigation via `src/config/menu.{en,ro}.json`.

Static pages and content-driven collections are prerendered. Dynamic catalogue routes
(`products`, `categories`, `partners`, `customer`, `product`, `vsu`, `solutions`) are
`prerender = false` and pull Payload data at runtime via `getPayload` against the same
SQLite database, so the `admin` workspace and `db/` must be present for these routes.

### Routing

- `[...lang]` root handles `ro` (unprefixed, default) and `en` (prefixed) locales.
- Static pages: `index`, `about`, `pricing`, `faq`, `team`, `contact`, `credits`, `terms`,
  `[page]`, plus `blog` (index / single / category / tag / page) and `case-studies`.
- Dynamic (Payload-backed) routes: `products`, `categories/[code]`, `partners/[code]`,
  `product/[code]`, `solutions`/`solutions/[code]`, `vsu`, `customers`.
- `api/[...path].ts` proxies the admin Payload REST API by default.
- `/admin` lists products from the hct.db in a Basecoat table (standalone page, no site
  layout). See [ADMIN.md](ADMIN.md) for details.

### Layout

- `src/layouts/Base.astro` is the site-wide shell used by every page. It wires up `Head`,
  a selectable header/footer (`Header`/`HeaderTwo` and `Footer`/`FooterTwo`), `GlobalScripts`,
  and `BackToTop`. Props control the header position, footer/header variant, dark background,
  SEO and JSON-LD output.
- `SinglePageLayout` / `BlogLayout` / `BlogSinglePageLayout` / `ServicesSingle` /
  `CaseStudiesSingle` compose the header/footer shell with shared page chrome
  (breadcrumbs, page title, sidebar, TOC).

### Main components

Layout and section components live under `src/layouts/components`.

- Header (`global/header`): `Header`, `HeaderTwo`, `TopBar`, `Navbar`, `MegaMenu`,
  `DropdownMenu`, `LanguageSwitcher`, `NavbarToggler`, `MenuItem`.
- Global (`global`): `Head`, `Footer`, `FooterTwo`, `Logo`, `SectionBadge`,
  `SectionTitle`.
- Sections (`sections`, the composable page building blocks): `Hero`,
  `FeaturesGrid`, `Services`, `Process`, `Pricing`, `Team`, `Testimonial`,
  `Faq`, `Contact`, `CTABar`, `CTAVideo`, `CTAGallery`, `Stats`, `StatsMarquee`,
  `Blog`, `BlogComment`, `CaseStudies`, `BrandLogos`, `SocialBar`, `About`,
  `ContactMap`, `HeroSection*`.
- Cards (`cards`, reused by sections): `ProductCard`, `PartnerCard`, `CategoryCard`,
  `MaterialCard`, `ServiceCard`, `TeamCard`, `BlogCard`, `CaseStudyCard`,
  `TestimonialCard`, `PricingCard`, `CustomerCard`, `FeaturesGridCard`,
  `SatisfactionClientsCard`.
- UI (`ui`): `ProductGallery`, `ProductsGrid`, `ProductVariants`, `PartnersOverview`,
  `PromosOverview`, `PageTitle`, `Pill`, `PillButton`, `IconButton`, `NewBadge`.
- Widgets (`widgets`): `Marquee`, `Accordion`, `Breadcrumbs`, `TableOfContents`,

  `VideoInline`, `Testimonial`.

### i18n

- `src/config/language.json` defines the two locales: `ro` (default, `ro-RO`) and `en`
  (`en-US`), each mapping to its `contentDir` (`romanian`/`english`).
- `src/i18n/{en,ro}.json` holds translatable UI strings accessed via `t()`.
- `src/content/<collection>` splits static content per locale folder.

## Development

From the repository root:

```bash
cp .env.example .env   # create the environment config (adjust values, see below)
bun install
bun run dev            # runs admin (3000) + web (4321) in parallel
bun run build
bun run e2e
```

### Fresh clone checklist

- Configuration is centralized in the repo-root `.env` (gitignored). Copy `.env.example`
  to `.env` and adjust `BASE_URL` (use `http://localhost:4321` for local dev) and
  `PAYLOAD_SECRET`. See DEVELOPMENT.md for the full variable list.
- `web/src/config/config.generated.json` is generated from `config.toml` by the
  toml-watcher and is gitignored. Run `bun run dev` or `bun run build` once before
  `bun run astro-check` (both regenerate the file on startup).
- The `admin` workspace needs the SQLite database at `db/hct.db` (bootstrapped on first
  `bun run dev`); dynamic web routes depend on it.
